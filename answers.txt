Section 5 - Create Constructor Methods

Question: Suppose you write one constructor that builds a DVD from its title, and then another that builds a DVD from its category. Does Java allow this? Why?

Answer:

No, because both constructors take a String parameter.

    DigitalVideoDisc(String title)
    DigitalVideoDisc(String category)

Java checks parameter types, not parameter names. So these two constructors have the same signature and cause a compile error.


Section 9.1 - Overloading by differing the type of the parameter

Question: Compare the varargs version with the array version. Which one do you prefer in this case, and why?

Answer:

Both work almost the same because varargs is treated as an array inside the method.

The difference is how we call them.

Array version:
    cart.addDigitalVideoDisc(new DigitalVideoDisc[]{dvd1, dvd2});

Varargs version:
    cart.addDigitalVideoDisc(dvd1, dvd2);

I prefer varargs because it's shorter and easier to use. It can also accept an array, so there's no need to use the array version.

We can't declare both methods in the same class because Java treats them as having the same signature.


Section 10 - Passing Arguments to Methods

Question: Is Java a pass by value or a pass by reference programming language?

Answer:

Java is always pass by value.

For primitive types, Java copies the value. For objects, Java copies the reference to the object.

a) After calling swap(), why do the titles stay the same?

Because swap() only swaps the local reference variables inside the method. It doesn't change the original references in main(), so the two DVDs stay the same.

b) After calling changeTitle(), why is the title of jungleDVD changed?

Because the copied reference still points to the same DVD object.

So when setTitle() is called, it changes the actual object's title.

Creating a new DVD and assigning it to the local parameter doesn't change the original reference in main().


Extra exercise - When static?

Question: People say "static kills OOP". When should we use static?

Answer:

Static belongs to the class instead of an object. Using too much static can make code less object-oriented, but it's still useful in some cases.

1. Constants: Values shared by all objects.
   Example: public static final int MAX_NUMBERS_ORDERED = 20;

2. Shared variables: For example, counting how many DVDs have been created.
   Example: private static int nbDigitalVideoDiscs = 0;

3. Utility methods: Methods that don't need object data, like Math.sqrt() or Math.max().

4. Main method: Java uses public static void main(String[] args) to start the program.

5. Factory methods: Static methods can be used to create objects, like Integer.valueOf().

6. Singleton: Used when we only need one shared instance, like Config.getInstance().

Conclusion:

I think static should be used when something belongs to the whole class or doesn't need an object. Otherwise, normal instance variables and methods are better.
